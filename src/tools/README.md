# 재생성 도구

평소에는 쓸 일이 없습니다. **`src/build.js` 만 돌리면 페이지가 다시 만들어집니다.**

아래 도구는 **원본 소재가 바뀌었을 때만** 씁니다. 전부 `sharp` 패키지가 필요합니다 (`npm i sharp`).

---

**디자인마다 바탕 사진 한 장과 마스크 한 벌이 있습니다.** 만드는 도구도 따로입니다 —
무지는 `extract-masks.js` + `alpha-masks.js`, 양면은 `split-piping.js` 하나입니다.

| 디자인 | 바탕 | 마스크 | 만드는 도구 |
|---|---|---|---|
| 무지 | `base.jpg` | `mask_{quilt,mattress,pillowF,pillowR,pillowL,pillowW}.png` | 1 + 2 |
| 양면 | `base_both.jpg` | `mask_{bothA,bothB,bothM,bothP}.png` | 2-1 |

---

## 1. `extract-masks.js` — 무지 부위 마스크 만들기

**언제:** 무지 배경 사진을 바꿀 때. 또는 부위를 더 나눌 때.

같은 구도에서 **색만 다른 렌더 이미지 3장**을 비교해, 색이 어떻게 변하는지로 부위를 갈라냅니다.
배경(마루·벽·커튼)은 세 장에서 변동이 **정확히 0**이라 자동으로 빠집니다.

```
입력  D:\01. 파마파미\00. 디자인\컬러시뮬레이션\
        80수 915번 브라운.jpg
        무지- 이불2006번 베개 914번.jpg
        901-2014.jpg
출력  base.jpg (흰색으로 되돌린 사진) + mask_*.png 6장
```

**주의 — `VAR_THRESHOLD`**
값이 높으면 **색이 거의 안 변하는 부위가 배경으로 잘려나갑니다.**
실제로 0.055에서 오른쪽 베개(흰색→민트→흰색)가 통째로 빠졌습니다. 현재 **0.018**.

**주의 — 시드 좌표**
부위 위치를 `SEEDS`에 직접 찍어둡니다. 사진이 바뀌면 좌표도 다시 잡아야 합니다.
자동 군집화(k-means)로는 베개들이 갈리지 않았습니다.

**주의 — 이 구도에는 흰색 바탕이 없습니다.**
그래서 `base.jpg` 를 **지어냅니다** — 부위마다 밝은 쪽 95% 값으로 나눠 흰색으로 되돌립니다.
양면 쪽(`split-piping.js`)은 진짜 흰 바탕이 있어 훨씬 깨끗합니다. 무지 컷의 흰 바탕이
생기면 그쪽 방식으로 옮기는 편이 낫습니다.

**주의 — 품질 82**
`base.jpg` 는 품질 82 + mozjpeg 로 씁니다 (191KB). 92로 두면 394KB라 페이지가 그만큼
무거워집니다. 82로 낮춰도 화소 평균 차이가 1.9/255라 눈에 안 보입니다 —
색을 곱해 얹는 바탕일 뿐이기 때문입니다. `base_both.jpg` 도 같은 값을 씁니다.

## 2. `alpha-masks.js` — 마스크를 투명도 채널로 변환

`extract-masks.js` 다음에 **반드시** 돌립니다.

CSS `mask-image`는 **투명도**를 읽습니다. 흑백 이미지로 두면 브라우저가 마스크를 무시해서
**색을 눌러도 아무 일도 일어나지 않습니다.** 흰색 RGB + 알파 형태로 바꿔줍니다.

## 2-1. `split-piping.js` — 양면 디자인의 사진과 마스크 (삥 구도)

**언제:** 양면 사진을 바꿀 때. `alpha-masks.js` 와 **무관하게** 혼자 돕니다 (알파까지 직접 씁니다).

```
입력  D:\...\컬러시뮬레이션\
        삥_시뮬레이션_(바탕).jpg                     ← 침구가 전부 흰색
        매트리스(아이보리)+이불(메로나)+라인(노랑).jpg
        양면.jpg
        양면1.jpg
출력  base_both.jpg (167KB)
      mask_bothA.png 앞면(겉)      mask_bothB.png 뒷면(안)
      mask_bothM.png 매트리스커버   mask_bothP.png 삥(테두리)
```

**바탕이 흰색이라 `사진 ÷ 바탕` 을 하면 주름 그늘이 지워지고 염색 색만 남습니다.**
세 장을 이어 붙인 9차원 값이 부위마다 다른 지문이 됩니다. 흰 바탕을 지어내는
`extract-masks.js` 보다 훨씬 깨끗합니다.

**주의 — 이불과 베개는 안 갈립니다**
색 사진 세 장이 전부 베개를 이불과 같은 색으로 칠해놨습니다. 따로 고르게 하려면
**베개만 이불과 다른 색으로 칠한 렌더**가 한 장 더 있어야 합니다.

**주의 — 삥은 밝기로 잡습니다**
2px짜리 얇은 선이라 덩어리 나누기로는 계단이 집니다. `양면.jpg` 에서만 삥이 남색(아주 어둡다)인
것을 이용해, **밝기비가 얼마나 떨어지는지**로 알파를 매깁니다 (`PIP_HI` · `PIP_LO`).
천 마스크는 `1 - 삥알파` 만큼 깎아 겹치지 않게 합니다.

**주의 — 알파를 딱 붙입니다**
안쪽 값을 그대로 두면 254·253·255로 자글거려 PNG가 **열 배**로 커집니다 (312KB → 24KB).
0.86 위는 255, 0.14 아래는 0으로 붙이고 가장자리 띠만 중간값을 남깁니다.

**주의 — `SEED` 와 `SHOTS` 순서**
덩어리 씨앗을 세 장에서의 색 비율로 박아뒀습니다. 사진이 바뀌면 다시 재야 합니다.
앞뒤는 `양면.jpg`(`WARM_SHOT`)에서 **붉은기가 적은 쪽이 겉면**입니다 — 뒤집히면 알려줍니다.

## 2-2. `design-cards.js` — 페이지에 들어가는 사진 만들기

**언제:** 바탕 사진·마스크를 다시 만들었을 때. 디자인을 더할 때. 카드 색을 바꿀 때.

```
입력  base.jpg + mask_*.png  /  base_both.jpg + mask_both*.png
출력  card_plain.jpg · card_both.jpg  (520px 정사각, 각 25KB)
```

**둘 다 같은 색표(`C`)를 씁니다.** 색을 따로 적어두면 대표가 색을 바꿀 때 한쪽만 바뀝니다.
**표지 사진은 여기서 안 만듭니다** — 실제로 찍은 사진이라 `brand-hero.js` 가 따로 맡습니다.

**카드 두 장은 사진이 달라도 같은 색으로 칠합니다** — 이불은 아몬드 밀크, 매트리스커버는 베링씨.
카드마다 색을 다르게 하면 손님이 「어느 쪽이 예쁜가」를 고르게 되어 디자인 차이가 묻힙니다.
양면 카드의 삥은 **앞면 색으로 덮어 안 보이게** 합니다 — 페이지에서도 그렇게 씁니다.

**주의 — `crop` 은 사진마다 따로**
사진 비율이 다릅니다 (무지 1200×1500, 양면 1200×1600). 이불 **앞면과 젖혀진 뒷면이 둘 다**
들어와야 양면 카드에서 「두 색」이 보입니다. 침대 전체를 담으면 작은 카드에서 이불이
너무 작아져 차이가 안 보입니다. crop 이 사진 밖으로 나가면 **에러로 멈춥니다.**

## 2-3. `brand-hero.js` — ① 표지에 까는 침구 사진

**언제:** 표지 사진을 바꿀 때.

```
입력  D:\...\컬러시뮬레이션\표지사진.jpg   (실제로 찍은 사진, 3024×4032)
출력  hero.jpg   (900px, 1.94:1, 54KB)
```

**이건 실제로 찍은 사진입니다** [대표, 2026-08-06]. 카드 사진처럼 흰 바탕에 색을 입혀
만든 것이 아니라, 자르고 줄이는 일만 합니다. 그래서 `design-cards.js` 와 떼어 두었습니다.

**주의 — 가로로 길어야 합니다.** 세로로 길면 사진만으로 첫 화면이 다 차서 브랜드 글이
안 보입니다. 900px 면 폰(430px) 2배 화면까지 덮습니다 — 더 키워봐야 안 보이고 무겁기만 합니다.

**주의 — 아래 띠가 어수선하지 않은 자리를 고르십시오.**
그 위에 워드마크가 걸쳐 얹힙니다. 지금 자리는 아래가 흰 매트리스커버라 글자가 잘 앉습니다.
밝은 침구 위라 `.bshot::after` 의 그늘을 아래쪽에서 0.56까지 올려 두었습니다 —
**사진을 바꾸면 이 값도 같이 봐야 합니다.**

**주의 — 원본을 `컬러시뮬레이션` 폴더에 두십시오.**
대표가 새 사진을 주면 그 폴더에 `표지사진.jpg` 로 넣습니다. 바탕화면처럼 지워지기 쉬운
자리를 가리키면 다시 만들 때 도구가 멈춥니다.

## 2-4. `brand-logo.js` — 워드마크 다듬기

**언제:** 로고가 바뀌었을 때. 거의 쓸 일이 없습니다.

```
입력  D:\...\01. 자사몰 이미지\자사몰 로고.png   (검정 글씨 + 흰 배경)
출력  logo.png   (900×79, 6KB, **투명도만** 담긴 그림)
```

**색을 안 담습니다.** 밝기를 뒤집어 알파로 만들어두고, 페이지에서 CSS 마스크로 얹은 뒤
`background-color` 로 색을 줍니다. 그러면 한 장으로 밝은 화면·어두운 화면·사진 위를
다 감당합니다. 원본을 그대로 올리면 어두운 화면에서 **흰 네모**가 보입니다.

**주의 — 로고 시트(`02. 브랜드 로고/로고.png`)를 쓰지 마십시오.**
아래 영문이 `INSTITUE OF BEDDING RESEARCH` 로 **오타**입니다 (`INSTITUTE`).
그 줄이 없는 「자사몰 로고.png」 를 원본으로 씁니다. [대표, 2026-08-06]
그 시트에서 뽑은 **브랜드 색**은 `README.md` 에 적어두었습니다.

## 2-5. `subset-fonts.js` — 폰트를 쓰는 글자만 잘라내기

**언제:** **표지 문구나 안내 문구를 바꿨을 때.** 폰트를 바꿀 때.

```
입력  %LOCALAPPDATA%\Microsoft\Windows\Fonts\Paperlogy-7Bold.ttf     (1,277KB)
      %LOCALAPPDATA%\Microsoft\Windows\Fonts\Pretendard-Regular.otf  (1,615KB)
출력  font-head.woff2 (28KB) · font-body.woff2 (62KB)
```

한글 폰트는 통째로 넣으면 두 벌 3MB 라 페이지에 못 넣습니다. 이 페이지가 쓰는
**584자만** 남기면 90KB 로 줄어듭니다. `npm i subset-font` 가 필요합니다.

**주의 — 두 번 돌려야 합니다.**
글자 목록을 **만들어진 `index.html`** 에서 뽑습니다 (문구를 코드 여기저기서 만들어서
소스만 봐서는 셀 수가 없습니다). 그래서 `build → subset → build` 순서입니다.
폰트는 글자를 더하지 않으므로 두 번째 build 뒤에도 목록은 그대로입니다.
폰트 파일이 없으면 build 가 **멈추지 않고 경고만 하고 넘어갑니다** — 처음 만들 때는
폰트가 있을 수 없기 때문입니다.

**주의 — 문구를 바꾸고 안 돌리면 티가 안 납니다.**
새로 들어간 글자만 기기에 깔린 글꼴로 떨어집니다. 한 글자씩이라 눈에 잘 안 띕니다.

**주의 — 폰트가 어디 깔렸는지.**
윈도우가 「모든 사용자」로 설치하면 `C:\Windows\Fonts`, 「나만」이면 사용자 폴더입니다.
도구가 둘 다 봅니다. 대표는 `C:\Windows\Fonts` 에 넣었다고 했는데 실제로는
사용자 폴더로 갔습니다 — 레지스트리(`HKCU:\...\Fonts`)를 보면 실제 경로가 나옵니다.

**주의 — 라이선스.**
Pretendard 는 OFL, Paperlogy 도 웹폰트 사용을 허용합니다. **폰트를 바꿀 때는
웹 임베딩이 허용되는지 먼저 확인하십시오.**

## 3. `extract-colors.js` — 컬러차트에서 102색 뽑기

**언제:** 원단 색이 추가·변경될 때.

```
입력  D:\01. 파마파미\06. 협력업체\프린톤(컬러칩작업)\최종 수정본\1차수정분\JPEG\  (13장)
출력  swatches.json
```

번호·영문명·한글명·번수는 **차트 이미지를 직접 읽어 코드 안에 적어둔 값**입니다 (`CHART` 상수).
색상값만 이미지에서 자동으로 뽑습니다.

**주의 — `rowY`**
칩이 놓인 줄의 세로 위치를 비율로 직접 적어뒀습니다. 자동 검출은 제목 줄이 섞여서 실패했습니다.
**차트 레이아웃이 바뀌면 이 값을 다시 재야 합니다.**

## 4. `verify.js` — 합성 결과 확인

브라우저 없이 마스크가 제대로 맞는지 봅니다. 결과는 `verify.jpg`.
**마스크는 투명도 채널을 읽어야 합니다** — 색(RGB)을 읽으면 화면 전체가 물듭니다.

## 전체를 다시 만드는 순서

```
node src/tools/extract-masks.js     # 무지 부위 마스크 + 흰색 바탕
node src/tools/alpha-masks.js       # 투명도 채널로 변환 (건너뛰면 색이 안 먹힘)
node src/tools/split-piping.js      # 양면 바탕 + 마스크 4장 (건너뛰면 빌드가 멈춤)
node src/tools/design-cards.js      # 디자인 카드 2장 — 위 둘 다 끝난 뒤에
node src/tools/brand-hero.js        # ① 표지 사진 (표지 사진이 바뀌었을 때만)
node src/tools/brand-logo.js        # 워드마크 (로고가 바뀌었을 때만)
node src/tools/extract-colors.js    # 컬러 102색
node src/build.js                   # index.html — 글자가 다 들어간다
node src/tools/subset-fonts.js      # 그 글자만 남긴 폰트 두 벌
node src/build.js                   # 이번엔 폰트가 박힌다
```

마스크와 색이 그대로면 **마지막 셋만** 돌리면 됩니다.
**문구를 손댔으면 반드시 셋을 다 돌리십시오** — build 만 다시 하면 새로 들어간 글자가
심은 글꼴에 없어서 그 글자만 다른 글꼴로 나갑니다.
